# Nexa 2.4.0 — Agent 原生语言与可靠运行时

Nexa 2.4.0 将 `.nx` 的语言声明贯通到统一编译器和 AgentRunner。人和模型可以编写相同的 Agent、工具、Protocol 与 flow，运行时统一处理 provider 协议、预算、审批、恢复和事件记录。Python 是参考实现，Rust AVM 随源码发布明确的能力子集。

## 安装与发行物

需要 Python 3.10+。在已激活的虚拟环境安装本项目的 GitHub Release wheel：

```sh
python -m pip install https://github.com/Nexa-Language/Nexa/releases/download/v2.4.0/nexa_lang-2.4.0-py3-none-any.whl
nexa --version
```

版本输出为 `Nexa v2.4.0`。使用 uv 创建包含可选 provider、终端和 MCP 依赖的环境：

```sh
uv venv --python 3.12
uv pip install "nexa-lang[anthropic,terminal,mcp] @ https://github.com/Nexa-Language/Nexa/releases/download/v2.4.0/nexa_lang-2.4.0-py3-none-any.whl"
.venv/bin/nexa --version
```

PyPI 的 `nexa-lang` 由另一项目使用；本版本通过上面的完整 URL 分发。模型凭据按 [运行契约](../runtime-v2.4.md#模型协议) 配置。编译和纯计算无需模型服务。

[GitHub Release](https://github.com/Nexa-Language/Nexa/releases/tag/v2.4.0) 提供：

- `nexa_lang-2.4.0-py3-none-any.whl`：Python 编译器、运行时、CLI 与包内 `.nx` 标准库。
- `nexa_lang-2.4.0.tar.gz`：Python 源码发行包，可独立重建 wheel。
- `SHA256SUMS`：上述发行包的 SHA-256 清单。
- GitHub 自动生成的源码归档：包含 Rust AVM、示例、测试和文档。

在下载目录执行 `shasum -a 256 -c SHA256SUMS` 核对附件。完整源码安装固定到发行 tag：

```sh
git clone --branch v2.4.0 --depth 1 https://github.com/Nexa-Language/Nexa.git
cd Nexa
uv sync --locked --all-extras
uv run nexa --version
```

## 本次升级

- **统一编译入口**：CLI、SDK、嵌入式 API、inspect 与 validate 共用模块加载、递归 include、AST 与源位置。生成 Python 在返回成功前通过语法检查；wheel 内包含标准库。
- **声明语义修复**：多阶段 `>>` 管道执行全部 Agent；整数历史限制、输出 token 上限及 limit/timeout/retry 装饰器传入运行配置。不支持的管道阶段在编译时失败，避免静默跳过。
- **可靠 Agent 执行**：文本、Protocol、流式和精确缓存共用 AgentRunner；每次 `execute()` 返回独立 RunState，`run()` 保持有序连续会话。调用次数、token、总时限、取消和终态统一记账。
- **原生 provider 协议**：Chat Completions、Responses、Anthropic。Responses output items / encrypted reasoning 与 Anthropic content blocks / thinking 签名按原生格式保留；截断、拒绝及不完整流显式失败。
- **工具策略与审批**：工具暴露集、JSON Schema、预算与审批共享执行边界。`nexa agent` 保存待审批调用，支持按调用批准、拒绝和恢复；Nexa Code 使用相同机制执行实际文件修改和验证命令。
- **持久恢复**：SQLite checkpoint 使用 revision 检测并发冲突。工具副作用前写入执行日志，完成结果可重用；超时或断连造成的未知结果需核实后恢复。大输出存入有界 artifact，并提供分段读取。
- **连续任务与工具链接口**：`NexaAgent.continue_run()` 从已结束且副作用确定的运行创建新一轮，保留合法历史及原生 provider 状态，重新建立预算、期限与审批；父子运行可以追踪。`inspect --format json` 提供声明的原文件及起止位置，供编辑器导航使用。
- **MCP 与并发生命周期**：使用官方 MCP SDK 的 stdio/HTTP 传输，远程工具默认需要审批。并行运行有界、结果有序；flow Actor 的邮箱、预算、取消和 await 生命周期统一收束。
- **可核验结果**：`verify` 失败终止成功路径；`.nxintent` 区分 pass、fail、skip、error。示例清单逐项标明支持状态。

## 迁移注意事项

1. `exit_when` 使用精确状态比较。检查旧程序中的自由文本包含判断，改为明确的状态值或布尔条件。
2. `verify`、Protocol/schema 校验参与真实执行；输出不满足条件时返回失败，调用方应处理失败状态。
3. 审批只接受明确的布尔结果。Nexa Code 的写文件与命令执行逐次等待审批；总超时包含审批等待时间，首次运行时应设置足够的 `--timeout`。
4. checkpoint 恢复检查程序、provider、工作区与预算的一致性。未知副作用保留 `started`，核实外部结果后通过 reconcile 继续；自动重试该调用可能重复产生副作用。
5. 普通 Python 工具在宿主进程执行，取消依赖工具协作。声明 `sandbox: true` 时必须提供隔离执行器，否则执行失败。快照恢复内存及会话，外部文件和服务副作用保持实际状态。
6. Context 限额采用保守的 UTF-8 字节上界；需要保留的原生 provider items 超限时显式失败，调用方应缩短输入。
7. `.nxs` 按父目录到程序所在目录合并，就近配置覆盖父目录。旧版本的反向覆盖错误已修复，迁移时核对项目实际选用的 endpoint 和 model。
8. 同一任务恢复使用 `execute(state=...)`，新一轮追问使用 `continue_run(previous, ...)`。待审批或运行中的状态先恢复或取消；有未知副作用时先核实结果，再开始下一轮。

公开的 `src.*` Python 导入路径保留。完整状态、退出码与恢复方式见 [运行契约与迁移](../runtime-v2.4.md)；安装和开发见 [开发说明](../development.md)。

## Rust AVM

Rust 支持声明初始化、整数/浮点算术、变量、跳转、返回及 Agent 调用。`Interpreter::set_agent_executor` 提供 provider 边界；工具、结构化输出及完整 Harness 使用 Python 运行时。未支持的 opcode 返回明确错误。

```sh
cargo build --manifest-path avm/Cargo.toml --locked --release
cargo test --manifest-path avm/Cargo.toml --locked --lib --test conformance --test wasm_execution
cargo test --manifest-path avm/Cargo.toml --locked --features wasm --lib --test conformance --test wasm_execution
```

`wasm` feature 使用 Wasmtime 48 LTS 执行真实模块，支持标量参数、实例状态、导出内存、fuel 和 epoch 中断。WASI imports 与引用类型参数尚未接入；Rust 使用构建当前锁定依赖所需的稳定工具链，本地验证版本为 1.97.1。

## 验证与已知范围

发布前的 macOS arm64 / Python 3.12.13 快照：**2171 passed、5 skipped、3 benchmark deselected**；Rust 默认 **140** 项通过，WASM feature **143** 项通过。63 个示例通过编译，12 个历史草案在清单中保留明确原因。远端 CI 配置覆盖 Linux 上的 Python 3.10/3.12/3.14 与 Rust 默认/WASM。

跨进程测试注入真实进程退出，覆盖“外部写入后中断”和“结果落库后中断”。Nexa Code 离线评测真实执行文件读写、两次审批和验证子进程，模型响应来自确定性 fixture。

历史语法的执行限制：struct/enum 构造、flow 的 `requires`/`ensures` 和 `defer` 存在已复现的生成代码缺口；`>> Reviewer ?? { ... }` 块式路由在编译时拒绝。以控制流结束的 flow 需要末尾顶层 `result` 赋值才能返回计算值；`std.json.parse` 当前返回文本，`@temperature` 尚未传给 provider。使用方式与复现见 [语言执行范围](../runtime-v2.4.md#语言执行范围)。

真实 provider 的鉴权、服务端兼容、质量、费用和延迟尚未测量。5 个 PostgreSQL 测试因缺少可选驱动跳过；MCP stdio 完成真实本地进程测试，HTTP server 端到端尚未单独验收。Rust Clippy 保留已记录的旧代码 warnings。详细环境、命令、日志及能力边界见 [验证记录](../../plan/evidence/2026-10-23-release-validation.md)。
