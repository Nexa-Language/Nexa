@tool("Add two integers")
fn add(a: int, b: int): int {
    python! """
return a + b
"""
}

agent Calculator uses add {
    prompt: "Use add to calculate the answer."
    timeout: 60
    max_tool_calls: 2
}

Configure a provider, then run nexa run calculator.nx. The runtime checks the tool arguments and call budget.

Nexa 2.4.0

Language declarations.
Runtime guarantees you can inspect.

The Harness Native design brings execution, tools, context, state, lifecycle and verification into the language. Version 2.4 connects those declarations across the Python compiler and runtime.

One compiler boundary

CLI, SDK and embedded API share recursive includes, source diagnostics, Harness validation and generated-code checks.

One execution lifecycle

Text, Protocol and streaming outputs share AgentRunner, explicit run states, call budgets, deadlines and cooperative cancellation.

Native model protocols

Chat Completions, Responses and Anthropic adapters retain tool calls, usage and native reasoning or thinking state.

Tools with explicit authority

Tool exposure, argument schemas and approvals are checked before dispatch. Requested isolation requires an actual isolated executor.

Durable, inspectable runs

SQLite checkpoints, revision checks and a tool journal support recovery. Uncertain side effects pause for reconciliation.

A measured Rust subset

The AVM shares semantic fixtures with Python. Optional Wasmtime execution covers guest memory, fuel limits and instance state.

Start small. Keep the evidence.

From your first flow to a resumable agent

Humans and models use the same source files. Compile offline, configure a provider when needed, and inspect each run’s state and pending calls.

hello.nx · no provider required
flow main {
    result = 23 + 19;
    print(result);
}

nexa run hello.nx prints 42. Use nexa build hello.nx to inspect generated Python, or nexa inspect hello.nx --format json for program structure.

Migration and execution boundaries

Make completion explicit

Verification controls success

Failed verify checks stop the success path. Loop exit conditions compare exact states. Intent checks distinguish pass, fail, skip and error.

Recovery respects side effects

Completed tool results can be reused. Unknown outcomes require reconciliation. Snapshots restore in-memory state and conversations; external effects retain their actual state.

Isolation is an execution property

Ordinary Python tools run on the host and cancel cooperatively. A tool requesting a sandbox requires an isolated executor. The Rust WASM feature covers a documented subset.
