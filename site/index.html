Nexa 3.0.0

Goals, code and evidence.
One evolving program.

Open Programs extends the Harness Native foundation: the language owns what a program must achieve, the conditions under which it is accepted, and how its next revision becomes active.

Compilation includes resolution

Typed open goals can be implemented by a person or resolved by a model. The compiler enforces a shared budget and executes candidates and checks in OCI.

Revisions persist beyond a run

Activities stay pinned to immutable revisions. Checkpoints admit new versions; durable events and process leases support restart and conflict detection.

Evidence has a current context

Deterministic checks, model reviews and human decisions remain separate records. Changed inputs, policies or dependencies create new verification obligations.

Exact authority for workspace edits

Maintenance produces a reviewable patch. A grant binds its baseline, paths and evidence; a journal and retained originals protect edits during recovery.

Reuse carries its conditions

Local implementation capsules retain provenance, license, dependencies and evidence. A receiving task checks compatibility and revalidates under its current inputs.

The compiler can improve with you

The author protocol supports clarification and diagnostics. A diagnostic advice pass is selected after frozen tests, locked bootstrap and explicit approval.

Start small. Keep the evidence.

Start with a complete goal. Then open it.

answer.nx · explicit implementation
language "3.0"
program Answer {
    goal answer() -> Int {
        intent "Return 42"
        implementation value 42
    }
}

nexa check answer.nx --json validates the source without Docker or credentials. The explicit value is the implementation; open goals let a configured model propose one.

Migration and execution boundaries

Make completion explicit

A versioned language boundary

language "3.0" selects Open Programs. Existing Agent and flow sources retain their 2.4 entry point. Legacy state exports into an inert archive with an explicit conversion report.

Recovery respects side effects

Unknown non-idempotent effects require reconciliation. Patch application preserves original files in recovery directories. Cross-file updates use a journal and require storage for retained originals.

Isolation is an execution property

Open Programs candidates run as non-root in offline, resource-limited OCI containers without host mounts or credentials. Legacy Python tools keep their documented host semantics; Rust retains its 2.4 subset.
